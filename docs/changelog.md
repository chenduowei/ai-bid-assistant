# Changelog

> 版本历史记录。当前稳定版为 **v1.0.6**，以长期使用为主。

## [1.0.6] - 2026-11-27

### 项目卡片展开 / 收起的丝滑度

用户实测「点开项目时列表整体向下挪一点，不够丝滑，有掉帧感」。三处根因一起修：

- **第 0 帧不再有边距跳变**（`css/views.css`、`css/breakpoints.css`）：详情区的 `margin` / `padding` / `border-top` 原来只写在 `.project-details.collapse.expanded > .collapse-inner` 上、又不参与 `0fr` 高度裁切，点开的瞬间就长出 34px 把下面的列表硬顶下去一截。现在 `.project-details > .collapse-inner` 恒为「只有左右留白（`0 var(--sp-4)`，手机同档）、上下 0、无边框」，上下留白与分隔线交给新内层 `.project-details-body`，跟着 `0fr → 1fr` 的高度一起露出来——收起态 `.collapse-inner` 高度精确为 `0px`，第 0 帧没有任何可见变化。
- **卡片自身的 6px 外边距也不再第 0 帧跳**（`css/views.css`）：`.project-item.expanded` 的 `margin: 6px 0` 之前是瞬变（本文件里两条 `.project-item` 各写一份 `transition`，后一条把 `margin` / `background-color` / `border-radius` 全盖掉了），展开时列表还会额外硬跳 12px。现在过渡清单合成一份，外边距、圆角、底色与高度同一条 320ms 弹簧曲线一起走。
- **先填详情、再起跑过渡**（`app.js`、`js/ui.js`）：`toggleProjectDetails` 原来先加 `.expanded` 再 `fillProjectDetails`，同一帧里既要解析 1~2KB 的新详情 DOM、又要起跑 `grid-template-rows`，移动端开头几帧就丢了。现在先补填详情，紧接着 `void details.offsetHeight` 在 `0fr` 状态下把内容尺寸同步算完，再加 `.expanded` 起跑——仍然完全同步，测试不受影响；`focusProjectInList` 的就地展开（`expandProjectCard`）同样先填后展开。
- **`.collapse` 只留一份**（`css/components.css`）：这组规则原来在同一文件里写了三遍，最后一遍把曲线覆盖成 `--ease-out`、并把 `.collapse-inner` 的过渡整条换成 `opacity + transform`，弹簧曲线等于没生效。现在统一为 `grid-template-rows var(--dur-slow) var(--ease-spring), opacity var(--dur-quick) var(--ease-standard)`；`.collapse-inner` 仍是 `min-height: 0` + `overflow: hidden` + 零 `padding` / `margin`，保留给 `.form-body` / `#optionalBody` 的 `padding-top` 过渡兜底。
- **回归测试**：新增 `tests/v106-smooth-expand.test.js`——详情内容只有一个内层包裹、`.project-details > .collapse-inner` 上下零留白而内层承担留白与分隔线、断点档位（≤680 / ≥1024）仍在、`.collapse` 与 `.project-item` 的 `transition` 各只剩一份且含弹簧曲线与 `margin`、两条展开路径都是「先填详情 + 强制布局 → 再加类」。

## [1.0.5] - 2026-11-27

### 修掉列表挪动与删除 / 恢复时的剩余闪烁

- **位置没变的卡片不再被挪一遍**（`js/ui.js`）：`syncListDom` 对账时此前无条件对每张卡片调 `insertBefore` / `appendChild`，即便它已经在正确位置。对已在树里的节点重复插入会先摘再插，浏览器把这一次当作新的入场动画——整页卡片（包括没改动的旧卡片）当场重播一次 `item-in`（淡入 + 上移）。现在先看目标位置：`anchor` 存在时只有 `el.nextElementSibling !== anchor` 才插；`anchor` 为 `null`（应是最后一张，旧的末尾元素已在第 1 步摘掉）时只有 `el !== listEl.lastElementChild` 才 `appendChild`；`replaceWith` 之后同样先比对再决定要不要多插一次。
- **删除 / 彻底删除的回声不再二次重绘**（`js/projects.js`）：`applyRealtimeChange` 的 `row.deleted_at` 分支与 `type === "DELETE"` 分支先看本地 `getState().projects` 里还有没有这个 `id`——本端刚 `deleteProject` / `deleteProjects` / `permanentlyDeleteProject` 已经移除并渲染过，几毫秒后原样推回来的回声直接 `return true`，不再 `removeLocalProjects` + `afterLocalChange()` 让列表再整一遍（这就是「删除项目闪两次」的第二下）。别的设备真删掉时本地还有这条，照旧移除并定向重绘。
- **回收站刷新不再重播入场动画**（`js/ui.js`）：`renderTrashList` 的卡片加上 `no-enter`。回收站每次恢复 / 彻底删除 / 加载更多后都整块重建 `innerHTML`，其余条目原来会一起重播 `item-in`，看着像点一次闪两下；现在除被操作的那条走了以外，列表原地更新、不闪。
- **回归测试**：新增 `tests/v105-no-flash.test.js`——无改动时零次挪动、只有换位的那张被挪、新建卡片照旧按序插入并带 `no-enter`、deleted_at / DELETE 回声不重绘、别的设备的删除照旧生效、恢复只提交一次且回声不重绘、回收站条目带 `no-enter` 且 CSS 里 `.project-item.no-enter { animation: none }` 生效。

## [1.0.4] - 2026-11-27

### 修复编辑保存后界面闪烁

- **Realtime 回声去重**（`js/projects.js`）：自己刚保存（或刚乐观改字段）的那一行被 Realtime 原样推回来时，先逐字段比对 `toUiProject(row)` 与本地同 id 项目（跳过只在内存里按需拉的 `pdfText`，`checklist` 按序列化比较）。完全一致就直接返回，不再 upsert + 定向重绘一次——保存后同一张卡片原来会被连续重建 2~3 次，第一次省掉。
- **定位不再整卡重建**（`js/ui.js`）：`focusProjectInList` 发现目标卡片已经在当前这一页的 DOM 里时，就地展开（加 `expanded`、补填详情、去掉 `inert`、更新箭头 aria）后滚动过去，不再 `renderAfterWrite({ changedIds: [id] })` 把整张卡片 `replaceWith` 掉；列表其余部分照旧对账。只有目标不在当前 DOM（换了筛选、在“加载更多”后面）时才走重建。
- **不再“摘掉 no-enter 重播入场动画”**（`js/ui.js`）：定位时加上的 `no-enter`（抑制 `item-in` 淡入 + 上移）以前会在 600ms / 柔光结束后被摘掉。摘掉等于把 `animation` 从 `none` 换回 `item-in`，浏览器当场重播一次：保存后 1.66 秒卡片又淡入一次，看着就是又闪一下。现在这个类留在卡片上（下次重建自然是新节点）。
- **移除 `content-visibility: auto`**（`css/views.css`）：`.project-item` 去掉 `content-visibility: auto` 与 `contain-intrinsic-size: auto 68px`——列表本来就有 50 条分页，不需要它；而 `replaceWith` / 定位滚动时，展开态卡片（远高于估算的 68px）会先按估算高度排一帧再测量撑开，正是那一下跳动的来源。
- **回归测试**：新增 Realtime 回声不重绘、定位不替换 DOM 节点、`.project-item` 不含 `content-visibility` 三组断言。

## [1.0.3] - 2026-11-26

- **日历订阅安全加固**：新令牌只把 SHA-256 哈希写入数据库，明文仅保存在生成设备的 `localStorage`；第 15 节迁移会把旧令牌和读取日志哈希化并清理明文，旧链接仍可继续使用。
